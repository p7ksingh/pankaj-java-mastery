1. What is Prototype Pattern?

Definition

The Prototype pattern is a GOF Creational Pattern. It creates a copy of an existing object through cloning, not from scratch level. According to GOF: "Specify the kind of objects to create using a prototypical instance, and create new objects by copying this prototype."

One line: Instead of creating objects from scratch (costly), clone existing cached objects to get new copies quickly.

Flyweight vs Prototype

AspectFlyweightPrototype
What it returnsThe SAME cached object (shared reference)A CLONE/COPY of the cached object (new instance)
Object ownershipShared among all clientsEach client gets its own independent copy
Modification safe?No (modifying affects everyone)Yes (each clone is independent)
Use whenObjects are immutable/read-onlyEach client needs a modifiable copy

2. The Problem

Problem

Creating new objects from scratch is a costly affair in Java. That needs more memory and CPU time. If we want certain bunch of objects to be created for multiple times, creating them every time from scratch level degrades the performance.

Problem: Every request creates objects from scratch EndUser 1 DB Server (ClientApp1) ---[1a]---> BookStore App ---[1b]---> Books info (db table) (buffer/cache) bookId bookName price EndUser 2 | List of [1c] 1001 C8J 9000 (ClientApp2) ---[2a]---> book objs <---------- 1002 BB 8000 | [2a] new objs from scratch! Every time hitting DB s/w and every time creating same bunch of objects is not really good practice. It will degrade the performance of the Application.

3. The Solution: Clone from Cache

Solution

Use Prototype Design Pattern which says: keep the objects that are created through costly process in cache memory and use cloning concept to create copy of objects from those cached objects.

Implementing Prototype Design pattern is nothing but creating bunch of objects through cloning process repeatedly by keeping the actual objects in the cache.

Solution: Clone from cached prototypes EndUser 1 buffer/cache DB Server (ClientApp1) ---[1a]---> [Book objs] <---[1b]--- Books info (db table) cached once! EndUser 2 | (ClientApp2) ---[2a]---> [2b] clone objs from cache (fast! no DB hit) First call: loads from DB, stores in cache Second call: clones from cache (no DB call)
Without cloning: With cloning: Student obj1 Student obj2 Student obj1 Student obj2 (Freshly (Another freshly (Freshly = (Student) obj1.clone() created created same created (object created object) object) object) through cloning process) Both created from scratch. obj2 is a copy of obj1. Costly: constructor + DB call. Cheap: memory copy only.

Four Components

ComponentRole
a) Prototype InterfaceDeclares the clone method (Cloneable interface in Java)
b) Concrete PrototypeImplements cloning. The actual object that gets cached and cloned.
c) Prototype Registry/FactoryMaintains a HashMap cache of prototype objects. Returns clones on request.
d) ClientGets cloned objects from the registry instead of creating new ones.

BookStoreFactory.java (Prototype Registry with cache)

package com.nt.factory;

import com.nt.model.Book;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

public class BookStoreFactory {
    private static Map<Integer, Book> bookCache = new HashMap<>();

    // Load from DB (simulated) and cache
    public static void loadBooks() {
        System.out.println("Loading books from DB (costly operation)...");
        Book book1 = new Book();
        book1.setBookId(1001);
        book1.setBookName("Core Java");
        book1.setBookType("IT");
        book1.setBookAuthor("James Gosling");
        book1.setPrice(9000);
        book1.setQty(50);

        Book book2 = new Book();
        book2.setBookId(1002);
        book2.setBookName("Business Basics");
        book2.setBookType("Non-IT");
        book2.setBookAuthor("Robert Kiyosaki");
        book2.setPrice(8000);
        book2.setQty(30);

        bookCache.put(book1.getBookId(), book1);
        bookCache.put(book2.getBookId(), book2);
        System.out.println("Books cached: " + bookCache.size());
    }

    // Returns CLONED book (not the original cached object)
    public static Book getBook(Integer bookId) throws CloneNotSupportedException {
        Book cachedBook = bookCache.get(bookId);
        if (cachedBook == null) {
            throw new IllegalArgumentException("Book not found: " + bookId);
        }
        return (Book) cachedBook.clone();  // clone, not the original!
    }

    // Returns cloned list of all books
    public static List<Book> getAllBooks() throws CloneNotSupportedException {
        return bookCache.values().stream()
            .map(book -> {
                try { return (Book) book.clone(); }
                catch (CloneNotSupportedException e) { throw new RuntimeException(e); }
            })
            .collect(Collectors.toList());
    }
}

5. Shallow Clone vs Deep Clone

Critical Concept

Java's default clone() method (super.clone()) performs a shallow clone. This is one of the most important distinctions in the Prototype pattern.

Shallow Clone (default)

Only the main object is cloned. Inner objects (references) are shared between original and clone. Changing an inner object via the clone affects the original.

Shallow Cloning (super.clone()): Original Book Cloned Book +--------------+ +--------------+ | bookId: 1001 | (primitive - | bookId: 1001 | (copied value) | price: 9000 | copied) | price: 9000 | | bookType ----|--+ | bookType ----|--+ +--------------+ | +--------------+ | v v BookType obj <--- SAME OBJECT! (shared reference) {type: "IT"} Changing bookType.setType("Science") via clone ALSO changes the original's bookType!
// Shallow clone - default behavior
@Override
public Object clone() throws CloneNotSupportedException {
    return super.clone();  // clones only primitives and references (not inner objects)
}

// Problem:
Book original = new Book();
original.setBookType(new ItBookType());  // inner object

Book clone = (Book) original.clone();
clone.getBookType().setType("Science");  // modifies SHARED inner object!

System.out.println(original.getBookType().getType());  // "Science" (BROKEN!)

Deep Clone

Both the main object AND all inner objects are cloned. Each clone has its own independent copy of everything. Modifying the clone does not affect the original.

Deep Cloning (manually clone inner objects): Original Book Cloned Book +--------------+ +--------------+ | bookId: 1001 | | bookId: 1001 | | price: 9000 | | price: 9000 | | bookType ----|--+ | bookType ----|--+ +--------------+ | +--------------+ | v v BookType obj1 BookType obj2 (SEPARATE object!) {type: "IT"} {type: "IT"} Changing clone's bookType does NOT affect original.
// Deep clone - manually clone inner objects
@Override
public Object clone() throws CloneNotSupportedException {
    Book cloned = (Book) super.clone();              // clone main object
    cloned.bookType = (BookType) bookType.clone();   // clone inner object too!
    return cloned;
}

// Now safe:
Book clone = (Book) original.clone();
clone.getBookType().setType("Science");  // modifies only clone's copy

System.out.println(original.getBookType().getType());  // "IT" (unchanged!)

Deep Clone using Serialization

For objects with many nested levels, manual deep cloning is tedious. An alternative is to serialize and then deserialize the object, which creates a completely independent copy.

// Deep clone via Serialization (all objects must implement Serializable)
public static <T extends Serializable> T deepClone(T obj) {
    try {
        ByteArrayOutputStream bos = new ByteArrayOutputStream();
        ObjectOutputStream oos = new ObjectOutputStream(bos);
        oos.writeObject(obj);
        oos.close();

        ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
        ObjectInputStream ois = new ObjectInputStream(bis);
        T cloned = (T) ois.readObject();
        ois.close();

        return cloned;
    } catch (Exception e) {
        throw new RuntimeException("Deep clone failed", e);
    }
}
AspectShallow CloneDeep Clone
Mechanismsuper.clone()Manually clone inner objects or use serialization
PrimitivesCopied by valueCopied by value
Object referencesShared (same reference)Cloned (independent copy)
PerformanceFast (one memory copy)Slower (multiple copies)
SafetyUnsafe if inner objects are mutableSafe (fully independent)
Use whenObject has only primitives/immutablesObject has mutable inner objects
Note on Immutable Classes

String, Integer, Float, Double are immutable classes. Shallow cloning is safe for these because they cannot be modified after creation. The shared reference causes no harm.

6. Full-Length Industry Project: Document Template System

Business Scenario

National Bank of India generates thousands of documents daily: loan agreements, account statements, KYC forms. Each document type has a complex template with headers, footers, formatting, legal text, and bank branding. Creating a template from scratch (loading from DB, parsing XML, applying styles) takes 500ms per document. Using the Prototype pattern, we load each template once, cache it, and clone it for each customer. Cloning takes under 1ms. The clone is then customized with the customer's specific data.

High-Level Design (HLD)

+---------------------------------------------------+ | SERVICE LAYER | | DocumentService | | - generateLoanAgreement(customerId) | | - generateAccountStatement(customerId) | | - generateKYCForm(customerId) | | (gets template clone, fills customer data) | +----------------------------+----------------------+ | v +---------------------------------------------------+ | PROTOTYPE REGISTRY | | DocumentTemplateRegistry | | - cache: Map<String, DocumentTemplate> | | - getTemplate(type): DocumentTemplate (CLONE) | | - loadTemplates(): void (one-time DB call) | +---------------------------------------------------+ | v +---------------------------------------------------+ | PROTOTYPE OBJECTS | | DocumentTemplate (abstract, implements Cloneable) | | - templateId, type, header, footer, legalText | | - formatting: DocumentFormatting (nested object)| | | | | LoanAgreementTemplate | | AccountStatementTemplate | | KYCFormTemplate | +---------------------------------------------------+

DocumentTemplate.java (abstract prototype)

package com.nbi.document.model;

import java.time.LocalDate;

public abstract class DocumentTemplate implements Cloneable {
    protected String templateId;
    protected String type;
    protected String header;
    protected String footer;
    protected String legalText;
    protected DocumentFormatting formatting;

    // Extrinsic data (filled after cloning, per customer)
    protected String customerName;
    protected String customerId;
    protected String generatedDate;

    protected DocumentTemplate(String templateId, String type) {
        this.templateId = templateId;
        this.type = type;
        // Simulate costly template loading (DB, XML parsing, style application)
        System.out.println("  [COSTLY] Loading template: " + type
            + " (simulating 500ms DB call)");
    }

    public void fillCustomerData(String customerId, String customerName) {
        this.customerId = customerId;
        this.customerName = customerName;
        this.generatedDate = LocalDate.now().toString();
    }

    public String render() {
        StringBuilder sb = new StringBuilder();
        sb.append("=== ").append(type.toUpperCase()).append(" ===\n");
        sb.append("Format: ").append(formatting).append("\n");
        sb.append(header).append("\n");
        sb.append("Customer: ").append(customerName)
            .append(" (").append(customerId).append(")\n");
        sb.append("Date: ").append(generatedDate).append("\n\n");
        sb.append(generateBody()).append("\n\n");
        sb.append(footer).append("\n");
        sb.append("Legal: ").append(legalText.substring(0, Math.min(80, legalText.length())))
            .append("...\n");
        return sb.toString();
    }

    protected abstract String generateBody();

    // DEEP CLONE: clone the main object AND the nested DocumentFormatting
    @Override
    public Object clone() throws CloneNotSupportedException {
        DocumentTemplate cloned = (DocumentTemplate) super.clone();
        cloned.formatting = (DocumentFormatting) this.formatting.clone();  // deep clone!
        // Reset extrinsic data (each clone starts fresh)
        cloned.customerName = null;
        cloned.customerId = null;
        cloned.generatedDate = null;
        return cloned;
    }

    public String getType() { return type; }
    public String getTemplateId() { return templateId; }
}

DocumentTemplateRegistry.java (Prototype Registry)

package com.nbi.document.registry;

import com.nbi.document.model.*;
import java.util.HashMap;
import java.util.Map;

public class DocumentTemplateRegistry {
    private static final Map<String, DocumentTemplate> cache = new HashMap<>();
    private static boolean loaded = false;
    private static int cloneCount = 0;

    public static void loadTemplates() {
        if (loaded) {
            System.out.println("Templates already loaded (skipping)");
            return;
        }
        System.out.println("=== Loading templates from DB (one-time costly operation) ===");
        long start = System.currentTimeMillis();

        cache.put("loan", new LoanAgreementTemplate());
        cache.put("statement", new AccountStatementTemplate());
        cache.put("kyc", new KYCFormTemplate());

        loaded = true;
        long elapsed = System.currentTimeMillis() - start;
        System.out.println("Templates loaded: " + cache.size() + " in " + elapsed + "ms\n");
    }

    public static DocumentTemplate getTemplate(String type) {
        if (!loaded) {
            loadTemplates();
        }

        DocumentTemplate prototype = cache.get(type.toLowerCase());
        if (prototype == null) {
            throw new IllegalArgumentException("Unknown template type: " + type
                + ". Available: " + cache.keySet());
        }

        try {
            cloneCount++;
            return (DocumentTemplate) prototype.clone();  // return CLONE, not original
        } catch (CloneNotSupportedException e) {
            throw new RuntimeException("Clone failed for template: " + type, e);
        }
    }

    public static String getCacheStats() {
        return "Templates cached: " + cache.size() + " | Total clones: " + cloneCount;
    }
}

Key observations from the project

  1. 3 template objects serve 106 document generations. Templates loaded from "DB" once. All subsequent calls clone from cache.
  2. Deep clone protects the cache. DocumentFormatting is a mutable nested object. Deep cloning ensures modifying one document's formatting does not affect the template or other documents.
  3. Extrinsic data reset on clone. The clone() method resets customerName, customerId, generatedDate to null. Each clone starts clean and is filled with customer-specific data.
  4. 100 documents generated in 8ms. Without prototype, loading 100 templates from DB would take 100 x 500ms = 50 seconds. With prototype, it takes 8ms.
  5. Template types are extensible. Adding a new template (e.g., ChequeBookTemplate) requires one new class and one registry entry. No other code changes.

7. When to Use and When NOT to Use

When to use Prototype

ScenarioExampleWhy Prototype
Object creation is expensiveLoading from DB, parsing XML, network callClone from cache instead of re-creating
Many similar objects neededGame entities, document templates, form copiesCreate one prototype, clone for each use
Object configuration is complexMulti-step builder result needs copiesBuild once, clone many times
Runtime object creationObjects whose type is determined at runtimeRegistry returns clone of correct prototype

When NOT to use Prototype

ScenarioWhy NOTUse Instead
Object creation is cheapCloning overhead not worth itnew keyword
Objects have circular referencesDeep cloning circular references causes infinite recursionSerialization-based cloning or Builder
Few objects neededRegistry overhead for 2-3 objects is excessiveDirect creation
